# 生成器插件

这里放的是“算密码”的规则：给一组输入，算出一个密码。它和密码库没有关系——
算出来的结果不写进 `vault.dat`，也不进导出备份。

目录里的每个 `.js` 都会被读成文本，由前端在 WebView 里执行。执行时作用域里只有一个变量
`PassletGenerators`，插件调用它的 `register` 登记生成器。

## 一、写一个插件

```js
PassletGenerators.register({
  id: "my-rule",                  // 必填。小写字母、数字、短横线，全局唯一
  name: "我的规则",                // 必填。界面上显示的名字
  fields: [                       // 必填。可以为空数组（不需要输入）
    {
      key: "feature",             // 必填。字母、数字、下划线或短横线
      label: "账户特征码",         // 必填。输入框前面的文字
      placeholder: "例如 qwerty", // 可选
      required: true,             // 可选。为真时没填就不算，界面上提示先填
      maxLength: 200              // 可选。1~200，默认 200，超出会被截断
    }
  ],
  generate(inputs) {              // 必填。inputs 是 { 字段key: 字符串 }
    return inputs.feature.toUpperCase();   // 必须返回非空字符串
  }
});
```

一个文件里可以 `register` 多次。某个定义写坏了只会跳过那一个，不影响同一文件里已经注册成功的。

## 二、文件放在哪

按下面的顺序取第一个可用的目录，界面上会显示当前生效的那个：

1. 环境变量 `PASSLET_GENERATOR_DIR`
2. 可执行文件同级的 `generators\` 目录
3. 调试构建回落到仓库根的 `generators\` 目录

只认目录内直接躺着的 `*.js`：子目录与其它扩展名一律忽略；单个文件上限 256 KB，且必须是
UTF-8 文本。每次进入“生成密码”视图都会重新扫描，改完文件切回来即可生效，不需要重启程序。

安装到别处之后（比如 `C:\Running\Passlet\`），把整个 `generators\` 目录拷一份到 exe 同级即可；
`frontendDist` 是嵌进二进制的，安装包里不含这个目录。

## 三、结果会被怎么检查

抛异常、返回非字符串、返回空串、超过 1024 个字符、含换行或控制字符——都会显示对应的错误，
而不是把坏结果塞进剪贴板。必填字段没填时结果区显示灰字提示，不算错误。

输入变化后会实时重算，**停止输入约一秒才写剪贴板**；中途算出的半成品不会进去。同一个结果
不会重复写。

## 四、边界与风险

插件是代码，不是配置：它在应用自己的 WebView 里执行，能访问 `window`，也就理论上能调用应用的
任意后端命令（包括读取密码库）。这不是遗漏，是可插拔的固有代价。因此：

- 只放自己写的、看得懂的插件；
- 不要从网络下载插件贴进来；
- 这个目录除 `example.js` 外都在 `.gitignore` 里，别改成“全部提交”。

如果哪天要支持不可信的第三方插件，正确的做法是换到独立的 JS 引擎里沙箱执行，而不是在 WebView
里加几行检查。
